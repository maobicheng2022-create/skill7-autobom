# 06 · 常见问题（排障）

## 环境 / 连接

**Q: `pywin32` 装了但 `import win32com.client` 报错**

- 用了 32 位 Python：`python -c "import struct;print(struct.calcsize('P')*8)"` 必须是 64
- pywin32 没注册：`python -m pywin32_postinstall -install`（管理员）
- 多个 Python 并存，装到了另一个：`python -m pip show pywin32` 看 Location 是否当前解释器

**Q: 报 `Invalid class string` / `80040154` / `GetActiveObject 失败`**

- SW 没启动：脚本会自动拉起；若被安全策略拦，手动正常双击打开 SW 再跑
- SW 是用 `-Embedding` 或服务方式启动的：关掉，用 `Start-Process sldworks.exe` 正常启动
- 权限/会话不同：脚本与 SW 必须是同一个 Windows 用户、同一个桌面会话

**Q: 脚本把 SW 重启了好几次，正常吗**

正常。`CloseDoc` 后 SW 不把内存还给 OS，几百个零件会吃 6–10 GB，流程在分类批次间/截图后/展开前主动重启。
不想让它退出 SW：加 `--keep-sw`（但大装配可能 OOM）。

## AutoBOM / 模板

**Q: SW 插件列表里没有 AutoBOM**

见 [03 文档第 6 节](03-AutoBOM与模板部署.md#6-常见问题)。核心：**SW 只读机器级 HKLM**，必须用**管理员**跑注册脚本（只写 HKCU 等于没注册，而且会盖住机器级）；注册后**重启 SW**，再在 工具→插件 勾选。

**Q: 页签出来了，但点某个按钮报“方法不存在 / 类型不匹配”**

这是 **SolidWorks 版本与 AutoBOM.SW.dll 的编译 interop 不匹配**：仓库里的 DLL 是按 **SW2025 interop（33.5.0.53）** 编译的，在 SW2022（30.1）上能加载（`ISwAddin` 的 IID 跨版本一致），但用到 2025 新增 API 的功能会失败。
→ 只能找原厂要一份对应版本编译的 DLL；注册表层面补不了。

**Q: 导出表缺列 / 列顺序不对 / 公式列是空**

`setting.json` 里模板定义与 `Template\*.xlsx` 不匹配。用仓库自带模板整体覆盖：

```powershell
# 先备份
python -X utf8 "skills\0-skill管理规范\scripts\autobom_backup.py"
# 覆盖
Copy-Item "templates\micDatas\pluginSettings\*" "C:\micDatas\pluginSettings\" -Recurse -Force
```

**Q: 型材类型（方管/圆管/长方管）判错**

型材类型由 `setting.json` 里模板公式按 `$宽/$高` 判定。改公式在 `AutoBOM.exe → 设置 → 模板 → 型材类型` 列，或直接改 JSON。
公式逻辑：宽≠高→长方管；宽∈{25,32,38,42,51,60,63,70,76,80,89,95,102,114,133,159,168}→圆管；否则方管。
**注意**：改了公式只影响之后导出的表，历史表不会自动重算（可重跑步骤 2）。

**Q: 钣金展开导出了 0 个 DXF，但 exe 返回 0**

`AutoBaiJinZhanKai.exe` 的返回码不可靠（统计 bug，成功也可能 rc=1），skill7 用**产物校验**判断。
0 个 DXF 的真实原因通常是：分类目录里没有 `.SLDPRT`、零件被锁定、SW 弹窗没点掉。

## 流程 / 产物

**Q: 合并报告里 `missing_in_csv` / `missing_in_dxf` 有值**

- `missing_in_dxf`：配料表有件但没展开图 → 展开失败（看步骤 8 日志/被锁定）
- `missing_in_csv`：DXF 有但配料表没有 → 多是分类目录残留旧副本，或图号没写进属性（步骤 0）

**Q: 型材数量都是 2**

型材宏按 `型材1.CSV` 的代号找件，找不到时默认数量=2。逐组跑时，每组的过滤 CSV 必须覆盖该组全部型材件（新版 `sw_weld_group.py prep-profile` 已保证）。

**Q: 焊接组的件还出现在总合并图里**

步骤 8.8 会把焊接组 DXF 移进 `钣金件\<组名>\`，总合并只吃根目录的。若还出现，说明组识别不对（看 `焊接分组.json`）。

**Q: 断点续跑报"缺产物"**

`--from N` 不会补前面步骤。缺什么先补什么：例如从 9 续跑要求 8 的 DXF 和 8.8 的分组已存在。

**Q: 中文/空格路径报错**

老版本 `glob` 在中文路径下有坑，`dwg2dxf.py` 已改 `os.listdir`。若仍报错，把图纸目录改成纯英文短路径试一次，确认是路径问题还是文件问题。

**Q: 产物 xlsx 打不开 / 乱码**

- CSV 是 `utf-8-sig`，Excel 直接双击能认；WPS 也可以
- 用 Python 读：`pd.read_csv(path, encoding='utf-8-sig')`

## 运行环境

**Q: 能跑在 Linux / 服务器上吗**

不能。SolidWorks、COM、AutoBOM、宏全是 Windows 桌面组件。

**Q: 需要联网吗**

不需要（除了 `git clone` / `pip install`）。

**Q: 能不能多台电脑同时跑同一套图纸**

不要。会互相覆盖分类目录和产物；同一份图纸串行跑。

**Q: 跑之前要关掉 SolidWorks 吗**

不用，脚本会连上现有 SW 并接管；但**不要边跑边手动操作 SW**。
